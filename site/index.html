s

A postfix language written right-aligned. Words push values onto a line from left to right, and the command at the end of the line consumes it, so every command stands at the right margin.

The machine runs s directly. s3 native compiles a program to plain Rust with no runtime in it, and s3 bend writes it as Bend 2. Every example on this site runs on the s machine in the page.

A line

swhat happens
5 x nThe command n takes the line 5 x: the name x holds the number 5.
x~ 2 + =~ >x~ pushes 5. + adds 5 and 2 and writes 7 to the name =. =~ pushes 7, and > prints it.
{a b c} xs /l/l splits the text at whitespace into the list xs: a, b, c.
a b c xs lEvery value before the list name is appended: xs is now a, b, c, a, b, c.

Four ways to run a program

commandwhat it makes
s3 run prog.sRuns the program on the machine: the reference semantics, with every command.
s3 build prog.sOne Rust program that carries the machine. What the program does before it first reaches outside (input, files, shell, threads, network, randomness, arguments) is done at build time.
s3 native prog.sRust with no machine in it. The program runs at build time; what is left is only what depends on input. Numbers are f64, lists are vectors changed in place, a script calling itself last is a loop, a fork over numbers is a vector kernel.
s3 bend prog.sThe same residue written as Bend 2, with F32 numbers and no vector kernels.

Measured once each on the Linux x86-64 machine these builds were made on. The list loop pushes 2,000,000 numbers onto a list, then sums them by index.

Lanes and SIMD

A fork over a list of numbers whose lanes do arithmetic, comparisons and writes under the flag runs as one program over the column of numbers. Each way of running does it differently:

waya fork over numbers10,000,000 lanes of 2 * 1 + 3 /
s3 runA vector program in the machine, in blocks of 2048 lanes.58 ms
s3 buildA compiled kernel for AVX-512, AVX or SSE2, chosen on the machine it runs on; NEON on ARM.41 ms
s3 nativeA compiled kernel for AVX-512, AVX2 or the x86-64 baseline, chosen when it runs, cut across the cores. On ARM, what rustc vectorizes for the target; not tested there.24 ms
s3 bendNo vector kernel: Bend has no SIMD. Lanes over a list map in parallel as a tree. 
one lane at a timeWhat the machine does with a fork it cannot vectorize.9.6 s

s3 build and s3 native as each reports with S_FORKS=1, s3 run and one lane at a time from the repository’s lanes benchmark, all on one Linux x86-64 machine with AVX-512. No kernel uses fused multiply-add, so each prints what the machine prints. What each way does not do yet is listed on the building page.

In the language

Names with forms

A name holds a text, a number, a list and a script. The last character of a word says what it does with the name: x~ reads, x# sets a number, x; adds one, x$ defines a script.

Scripts and tail calls

A brace becomes a script with name$. A call as the last word of a script is a tail call, so loops are scripts that call themselves.

Replacements

{code} 'word' >< makes a word run code. A script sees the replacements that existed when it was defined.

Lists and text

Push, pop, index, split and join, on lists that grow as values arrive.

Input, files, shell

stdin by line, files whole or by handle, the shell's output and exit code.

Threads and TCP

Workers that run other files and answer with code, and sockets through the same handles as files.

Lanes

A line splits into lanes that run the same words on their own copies of the names, and join, filed by index.

A standard library in s

Stack words, folds over the line, text, maths, checks and shell pipelines, written in s.

cargo build --release
./target/release/s3 run prog.s           # run on the machine
./target/release/s3 native prog.s -o prog # build plain Rust, needs rustc
./target/release/s3 bend prog.s -o prog   # build through Bend 2, needs bend
