Guide

The language from the first line to threads and lanes. Every example runs here; change it and run it again.

Running a program

A program is a text file of s. s3 run prog.s runs it on the machine; s3 prog.s a b runs it with the arguments a and b, which the program finds in the list args and the number argc.

Each example on this page is an editor. Change it and press Run or Ctrl+Enter; Reset brings the example back.

{hello, world} >

> prints a newline, then each value on the line after a space. >_ prints the values with nothing added.

The line

Words are separated by whitespace, newlines included, and taken from left to right. A word pushes a value onto the line, reads or writes a name, or is a command. A command consumes every value on the line as its arguments, in order, and the line is empty after it.

Values a line does not consume stay for the next command, wherever that command stands in the text. A program is written right-aligned so the commands line up at the right margin.

5 x n
x~ 2 + =~ >
3 4 total *  total~ >

The arithmetic commands write their result to the name =, or to the name given as a third value. =~ puts the result back on the line.

Values

12 -0.5
A word that reads as a number written the way s writes numbers is a number. Numbers are 64-bit floating point. They print in the shortest form that reads back the same, and negative zero prints as 0.
word
Any other word is pushed as itself.
{a text}
Braces hold text with spaces, newlines and nested braces. Inside the outer braces, ~name~ is replaced by the name's text when the brace is pushed.
'a text'
Quotes push the text as written, with no replacing.
{r}
A command word runs wherever it appears. Written in braces it is a text: 5 {r} n sets the name r, where 5 r n would run r first.
world w`
{hello ~w~} >
'~w~ stays as written' >

Names

A name holds a text, a number, a list and a script, each apart from the others. The last character of a word, after at least one other character, chooses what the word does with the name.

x~
Pushes x: its text when it has one, else its number, else 404. When that value is one word that runs (a command, a form, a replacement), it runs.
{~x~}
Pushes x's text inside a brace. It never runs.
x`
x's text becomes the line: the one value, or all of them joined with spaces. The line is emptied.
x#
x's number becomes the first value on the line, or 0. The line is emptied.
x; x:
Adds to x's number, or subtracts from it, the first value on the line, or 1.
x@
Takes the last value off the line into x's text.
x$
The line's text becomes the script x. A | in it is read as ~.
x. x..
Calls the script x. With exactly one value on the line, x. runs x that many times; x.. always calls once and leaves the line for the script.
:x
A name that starts with a colon belongs to the call it was written in. Each call of a script has its own.
0 i#  i;  i;  5 i;  i~ >
a b c x@  x~ >

The first form reads the value back after x@ took it off the line, so the line prints a b c again.

A few names belong to the machine: = holds results, r and rc the shell's output and exit code, err the last error, eof whether input has ended. The reference lists them all.

{>} p`
hello p~
hello {~p~} >

p holds the command >, so p~ runs it on the line hello. The brace reads p as text and pushes it.

Conditions

A comparison sets the flag ow and consumes the line. A word that ends in ? runs only when ow is set; one that ends in ! runs only when it is clear. The suffix goes on any word or form: >?, r#?, loop.?, <-?.

= !=
The same value, or a different one: numbers by value, everything else by text.
==
Equal as numbers.
<< >> <<= >>=
Less, greater, at most, at least, as numbers.
& ;
ow stays set only when it was set and the values are the same (&) or different (;).
!!
Flips ow.
4 x n
x~ 3 >>  {four is more than three} >?
x~ 3 <<  {not less} >!

Scripts

A brace followed by name$ is a script. name. calls it. <- returns from the script running; <-? returns when ow is set. A call that is the last word of a script is a tail call: the call replaces the running one, so a loop written as a script that calls itself runs in constant space.

{{hello again} >} hi$
3 hi.

With one value on the line, a call runs the script that many times. &&& does the same and sets n to the round, from 0.

{n~ >} round$
3 round &&&

A script that takes values from the line is called with ... Each call of fib below has its own :n and :a; it leaves its answer in r.

{:n#  :n~ 2 << :n~ r#? <-?  //  :n~ 1 - =~ fib..  r~ :a#  :n~ 2 - =~ fib..  :a~ r~ + =~ r#} fib$
20 fib..  r~ >

A script that calls itself last is a loop. This one reads stdin until it ends, then prints the count and the sum.

0 n#  0 s#
{x <_  eof~ 1 == <-?
 n;  s~ x~ + =~ s#
 loop.} loop$
loop.
n~ s~ >

Replacements

{code} 'word' >< makes the word run the code wherever it appears afterwards, command words included. \word is the command or the plain word, past any replacement.

{2 *} 'double' ><
5 double =~ >
{ {small} > } 'big' ><
big  \big >

Every definition has a generation. A script sees the replacements made before the script was defined, so a later definition of the same word changes the word everywhere after it and leaves older scripts as they were.

{ {old} > } 'w' ><
{w} f$
{ {new} > } 'w' ><
f.  w

Frames

k ( keeps the last k values on the line and puts the rest aside; ) puts them back in front of what the line holds then. ## pushes how many values the line holds. The standard library's words use frames to act on the top of the line and leave the rest.

1 2 3  1 (  10 + =~  )  >

Lists

a b xs l
Appends every value before the name to the list xs.
xs -l
Takes the last item off xs into the name $, or 404 when xs is empty.
xs i v [l]
Item i of xs into v. A negative i counts from the end. Outside the list, v keeps what it held.
v xs i l=
Sets item i of xs to v.
xs #l
The length of xs into =, or into the name given second.
xs l-
Deletes xs.
a b c xs l
xs 1 v [l]  v~ >
Z xs 0 l=  xs o l/ o~ >
xs -l  $~ >

Text

t xs /l
Splits the text t into the list xs at whitespace; with a third value, at that separator; at {}, into characters.
xs o l/
Joins xs into the name o with single spaces, or with a separator given third.
t #s
The number of characters of t into =, or into the name given second.
{a b c} xs /l
xs #l =~ >
xs o {-} l/ o~ >
{héllo} #s =~ >

Code as values

text ~
Runs the text as s.
table key ?)
The table is pairs of words, key then code. Runs the code after the key, or a default given third.
n name &&&
Runs the script n times with n set to the round.
{3 4 * =~ >} ~
{{one} >} one$  {{two} >} two$
{a one. b two.} b {{neither} >} ?)
{a one. b two.} z {{neither} >} ?)

Input and output

name <_
Reads a line from stdin into name, or into _. eof holds 1 once input has ended, else 0.
path text w
Writes the text to the file; +w appends; a b mv moves a file.
path name r
Reads the whole file into name. Without a name, into the name spelled as the path.
cmd <
Runs the command in sh: its output in r, its exit code in rc.
args argc
The command line as a list, and its length.
name <_  {hello ~name~} >
notes.txt {hello} w
notes.txt text r  text~ >
notes.txt { again} +w
notes.txt r  notes.txt~ >

Files in the page live in memory for the length of one run. The shell is not part of a browser, so the next example shows what s3 run printed.

{echo one; echo two} <  r~ >_  rc~ >
one
two

 0
args 0 a [l]  argc~ a~ >

Handles read and write a file in parts: path h mode f opens (r, w, a, r+, w+, a+), h line f_ writes a line, h v _f reads one, h ?eof sets eof, h f- closes. The reference has the rest.

Errors

An error stops the program with s: and the message on stderr, and exit code 1. {body} {handler} try runs the body; when it fails, the handler runs with the message in err. f and tcp take a script as their last value, which runs on failure the same way.

code <-- ends the program with that exit code.

{{missing.txt} r} {{caught: ~err~} >} try
{before} >  3 <--  {after} >

Threads and the network

file t starts a worker: its own machine, running the file. text i <t sends worker i a text, which it runs as code. When a message leaves code in the worker's name out, that is its reply; i >t waits for the reply and runs it in the sender. i -t closes the worker. files… *** runs files side by side and then runs each one's out in order.

A browser has no threads for the machine, so these examples show what s3 run printed. The worker file, threads_worker.s:

0 hits#
{hits;  {'got ~msg~ hits ~hits~' >} out`} handle$
threads_worker.s t
{ping msg` handle.} 0 <t
0 >t
{pong msg` handle.} 0 <t
0 >t
0 -t
{x} 0 <t  err~ >
 got ping hits 1
 got pong hits 2
 Invalid thread index

addr h mode tcp opens a connection: mode c connects, s listens and sets port, a accepts on the listener named first and sets peer. A connection takes f_, _f, ?eof and f- like a file. Here the client is a worker, so one program is both ends.

127.0.0.1:0 srv s tcp
rs_tcp_client.s t
{127.0.0.1:~port~ k c tcp  k {hello from the client} f_  k reply _f  {'client got: ~reply~' >} out`  k f-} 0 <t
srv conn a tcp
conn line _f  {server got: ~line~} >
conn {echo ~line~} f_
0 >t
conn line _f  conn ?eof  {after close, eof is ~eof~} >
conn f-  srv f-
127.0.0.1:1 x c {{connection refused, as expected} >} tcp
 server got: hello from the client
 client got: echo hello from the client
 after close, eof is 1
 connection refused, as expected

Lanes

A fork splits the line into lanes. ⟪a¦b¦c⟫ words ⨝ has three lanes; each lane's line is the line at the fork, its own values, then the words after ⟫. ⟪xs…⟫ has one lane per item of the list xs.

Each lane writes into its own copy of the names as they were at the fork. At the join ⨝ the names are as they were at the fork, and the lanes are held, lane 0 first.

collect
Puts every lane's line on the line, lane after lane.
xs into
Makes the list xs from the lanes' lines.
i lane
Brings back lane i's line, and reads its writes first until endlane.
{code} reduce
Folds the lanes' lines with the code, from lane 0.
{code} lanewise
Runs the code once in each lane.
lanes
Pushes how many lanes there are.
⟪1¦2¦3⟫ 10 * =~ ⨝ collect >
{1 2 3 4} xs /l
⟪xs…⟫ 2 * =~ 1 + =~ ⨝ ys into  ys o l/ o~ >
⟪1¦2¦3¦4⟫ ⨝ {+ =~} reduce >

The machine runs a fork over numbers with arithmetic and comparisons as one vector program over the column, a fork whose lanes hold code on threads, and anything else one lane at a time. s3 build and s3 native compile a fork over numbers to a SIMD kernel; s3 bend does not. The output is the same every way. With S_FORKS=1 a run, or a built program, reports on stderr how each fork ran and how long it took.

Loading files

A call of a name with no script runs the file of that name: std/line.s. loads the line library, helpers.s. runs helpers.s from the program's folder. Each library file loads once however often it is called. std/all.s. loads core, line, text, math and check.

std/line.s.
1 2 3 4 sum >
1 2 3 4 5 {2 mul} map >
1 2 3 4 5 6 {2 mod 0 eq} filter >
