Building

Run on the machine, build with the machine inside, or compile to Rust or Bend with no machine at all.

The commands

commandwhat it makes
s3 run prog.s [args…]Runs the program on the machine.
s3 rs prog.s [-o out.rs]One Rust program carrying the machine, with what the program does before it first reaches outside done at build time. --no-fold builds it as written.
s3 build prog.s [-o bin]The same, compiled with rustc -O.
s3 native prog.s [-o bin]Plain Rust with no machine in it, compiled with rustc; with -o prog.rs, the Rust only.
s3 bend prog.s [-o bin]Bend 2, run through bend; with -o prog.bend, the Bend only, beside its effect files.

Folding

A build runs the program at build time up to the first word that reaches outside the machine: stdin, files, the shell, threads, the network, random numbers or the arguments. The binary starts there, with what the program printed already written and its names, lists, scripts, replacements and line in place. A program that never reaches outside builds to its output.

s3 native

The program runs at build time on an abstract machine that holds every value it can know, and writes out as code only what depends on input. A loop whose rounds differ only in such values becomes a function, and a choice on such a value becomes a branch. What is left is written as Rust:

  • Numbers are f64 and print exactly as the machine prints them. Texts are shared strings.
  • A list is a vector shared by reference count, moved where it is read the last time and changed in place. A list that only ever holds numbers is a vector of f64.
  • A script that calls itself last is a loop. Scripts that call each other last fold into one loop at build time.
  • Before the Rust is written, one pass keeps only the parameters a function reads, the results a caller reads and the statements whose values are read, and passes a value read only as a number as a number.
  • Files, the shell, sockets and random numbers are calls into std. A worker message that does any of these runs on its own thread from <t to >t; one that does none folds away.
  • A fork over a list of numbers whose lanes give back numbers is one loop over the column, compiled for AVX-512, AVX2 and the baseline and chosen on the machine it runs on, and cut across its cores for long lists. It uses no fused multiply-add, so it prints what the machine prints. A remainder in a lane runs in vectors in a form exact for whole numbers below 2^53; when any input is not one, the column is taken again with the exact remainder.
  • A fork over a list of other values runs its lanes on threads in chunks. A fork with a known number of lanes that do nothing outside runs each lane as a function, the lanes split in halves over the spare cores.

All 30 programs of the corpus, the input programs and 300 walks of the cube example give what the machine gives.

s3 bend

s3 bend writes the same residue, after the same pass, as Bend 2. Numbers are F32, so a result past 24 bits of precision differs from the machine's. Bend runs effects on one thread, so a program whose worker waits on the program itself, as the TCP example does, does not finish there. 27 of the 30 corpus programs give what the machine gives; the three that differ are those cases.

What each way does not do yet

s3 run and s3 build carry the machine and do everything the language has. s3 native builds every program: what it cannot write without the machine (words written in Rust with -n, worlds, and the cases under What needs the machine) it builds with the machine in it, as s3 build does, and says so on stderr. These are the things s3 native and s3 bend do not do yet:

s3 native

  • A word that comes from input and would run as code, such as an argument that is a command word read with x~, stops the program with a message; the machine runs it. A program cannot know such words before it runs.
  • Worker files given to t and *** are built in. When the program starts it checks them, and a file changed since the build stops it with a message; s3 build runs the changed file.

s3 bend

  • Everything listed for s3 native, and the cases under What needs the machine, which s3 bend refuses.
  • No vector kernels: Bend has no SIMD.
  • F32 numbers: a result past 24 bits of precision prints differently from the machine.
  • Effects on one thread and no sockets: tcp, and a worker that waits on the program itself, do not work.

What needs the machine

These need the machine at run time. s3 native builds a program that has one with the machine in it and names the word and the line on stderr; s3 bend stops with that message:

  • Text that comes from input run as code: ~, a script or a replacement defined from it, or a replacement's value built from it.
  • A ?) table that comes from input.
  • A name or a list index that comes from input; a number from input where numbers have replacements.
  • A fork over a list from input whose lanes write a list or a script or end the program; into over such lanes when a lane's line holds more than one value; an error inside lanes inside a try.
  • A second message to a worker before >t takes the reply to the first; a thread index from input; a worker's error that depends on input.
  • A recursion whose end does not settle at build time; two paths that end differently and cannot be joined.
  • Lanes held from before a loop that the loop reads before it forks again.
  • A message to a worker, or a reply, built from input where the value lands outside a quoted text or a number.
  • A loop whose rounds set different names or open different frames in a way no number of rounds settles.

s3 build carries the machine, so it builds every program s3 run runs.
